# Таро-бот для Telegram: план первой итерации

## Цель первой итерации
- **Карта дня**: строго одна карта в сутки (с полуночи по минскому времени), изображение + описание, сгенерированное ИИ. Подписка на ежедневную рассылку.
- **Расклад из трёх карт**: пользователь пишет вопрос, бэкенд случайно выбирает 3 карты и их положения, ИИ трактует расклад.

## Принятые решения
| Тема | Решение |
|---|---|
| Язык | Python |
| Фреймворк | aiogram 3 (рекомендация) |
| База данных | PostgreSQL + SQLAlchemy + Alembic (рекомендация) |
| ИИ-модель | бесплатные тарифы; Groq основной, OpenRouter и Mistral запасные; при лимите или сбое бот переходит к следующему. Gemini недоступен из Беларуси. Запросы могут использоваться провайдерами для обучения — это допустимо |
| Проект | новый |
| Колода | все 78 карт; позже несколько колод на выбор пользователя |
| Изображения | хранятся на серверах Telegram (закрытый канал-хранилище), в базе только `file_id`; 1280 px по высоте, JPEG 90 |
| Перевёрнутые карты | изображение показывается перевёрнутым; в том числе для карты дня |
| Карта дня | у каждого пользователя своя случайная |
| Повторный запрос карты дня | ответ «вы уже получили карту дня» |
| Часовой пояс | для MVP один на всех: Минск (`Europe/Minsk`); пользователя о поясе не спрашиваем |
| Начало суток | полночь по Минску |
| Рассылка | в фиксированное время по Минску; если пользователь уже взял карту сам, рассылка ничего не присылает |
| Позиции в раскладе | без позиций, карты читаются вместе |
| Ограничения на расклады | в первой итерации нет (платные расклады позже) |
| Отправка расклада | альбом из 3 фото, затем текст отдельным сообщением (подпись к альбому видна только у одного фото и ограничена 1024 символами) |
| Ограничения тем вопросов | в промпте: здоровье, беременность, юридические и финансовые решения, другие люди — с оговоркой; смерть — мягкий отказ; признаки кризиса — поддержка и совет обратиться за помощью |
| Описание карты дня | заранее сгенерировано ИИ для 78 карт × 2 положения, хранится в базе; карта дня не тратит лимит ИИ |
| Обращение по имени в ответах ИИ | нет |
| Дисклеймер | одна строка в приветствии |
| Голос бота | «Шёпот Арканов»: тепло, немного мистически, без фатализма, на «вы» |
| Уточняющие вопросы после расклада | нет |
| История раскладов | пока не храним |
| Язык бота | только русский |
| Админка, аналитика | не в первой итерации |

## Этапы

### Этап 0. Каркас проекта — готово
- Python, uv, aiogram 3, SQLAlchemy, Alembic.
- Настройки (токен бота, ключ ИИ, адрес базы) берутся из `.env`.
- `docker-compose` с Postgres для локальной разработки.
- Бот получает сообщения через polling; способ работы на сервере решим позже.

### Этап 1. Структура данных — готово
Значение карты одно и то же, картинки зависят от колоды, поэтому новые колоды добавляются без переделки.

| Таблица | Поля |
|---|---|
| `cards` | 78 карт: код, название на русском, аркан, масть, номер |
| `decks` | колоды; пока одна |
| `deck_card_images` | колода, карта, путь к картинке, `file_id` Telegram для прямого и перевёрнутого положения |
| `users` | Telegram ID, имя, username, подписка; позже: выбранная колода, поля профиля, признак «заблокировал бота» |
| `daily_cards` | пользователь, дата по Минску, карта, положение, описание, источник (сам взял / рассылка); **уникальная пара «пользователь + дата»** |

Уникальная пара «пользователь + дата» гарантирует, что при двойном нажатии или одновременной рассылке пользователь не получит две карты.

### Этап 2. Колода и изображения — готово
- 78 карт добавляются в базу миграцией (русские названия, порядок Райдер–Уэйта: Сила 8, Справедливость 11).
- Картинки не хранятся ни в git, ни на сервере: скрипт `scripts/import_deck.py` один раз уменьшает их до 1280 px, делает перевёрнутые копии, публикует в закрытый канал-хранилище и сохраняет `file_id` в базу.
- Бот отправляет картинки только по `file_id`. После смены токена бота скрипт нужно запустить заново, поэтому исходники стоит сохранить.

### Этап 3. Основа бота — готово
- Пользователь регистрируется при любом сообщении (middleware), `/start` показывает приветствие.
- Главное меню: «Карта дня», «Расклад», «Подписка» (пока заглушки).
- Описание и команды бота задаются через API при запуске.
- Тесты на отдельной базе `<DB_NAME>_test`.

### Этап 4. Работа с ИИ — готово (код); осталось проверить на живых ключах
- `bot/ai`: один клиент для всех OpenAI-совместимых провайдеров, порядок в `AI_PROVIDERS`; при лимите (429) провайдер откладывается, при сбое — переход к следующему.
- Промпты карты дня и расклада в `bot/ai/prompts.py`, ответ ИИ превращается в безопасный HTML для Telegram.
- Таблица `card_descriptions` и скрипт `scripts/generate_descriptions.py` для 156 готовых описаний.
- `scripts/try_prompt.py` — ручная проверка промптов и сравнение провайдеров.

### Этап 5. Карта дня
1. Вычислить сегодняшнюю дату по Минску.
2. Если запись на эту дату есть — ответить «вы уже получили карту дня».
3. Если нет:
   - случайно выбрать карту и положение (`secrets` / `SystemRandom`);
   - сохранить запись;
   - взять готовое описание из `card_descriptions`;
   - отправить фото с описанием.

### Этап 6. Подписка и рассылка
- Кнопка подписки / отписки.
- Фоновая задача каждые N минут находит подписчиков, у которых нет карты на сегодня, когда по Минску наступило время рассылки, и выдаёт им карту по логике этапа 5.
- Отправка очередью с ограничением скорости (лимиты Telegram и бесплатной ИИ-модели).

### Этап 7. Расклад из трёх карт
1. Пользователь нажимает «Расклад», бот просит вопрос и ждёт ответа.
2. Бот выбирает 3 разные случайные карты, положение каждой случайное.
3. В запрос к ИИ идут вопрос и карты с положениями.
4. Пока ИИ отвечает, бот показывает «печатает…».
5. Отправка альбома из 3 фото, затем текста трактовки.

### Этап 8. Проверка и запуск
- Тесты:
  - выдача карты дня на границе суток по Минску;
  - нет повторной карты за день;
  - рассылка пропускает тех, кто уже взял карту сам.
- Развёртывание на сервер (место не выбрано).

## Открытые вопросы
1. **Ошибка ИИ при раскладе**: что ответить пользователю, если ни один провайдер не ответил.
2. **Время рассылки**: какое именно время по Минску.
3. **Отписка**: устраивает ли кнопка «Подписка» в меню.
4. **Поля профиля**: какие собирать и когда.
5. **Хостинг**: где будет работать бот, webhook или polling.

## Отложено после MVP
- Часовой пояс пользователя (сейчас у всех Минск).
- История раскладов в базе.
