# Таро-бот для Telegram: план первой итерации

## Цель первой итерации
- **Карта дня**: строго одна карта в сутки (с полуночи по часовому поясу пользователя), изображение + описание, сгенерированное ИИ. Подписка на ежедневную рассылку.
- **Расклад из трёх карт**: пользователь пишет вопрос, бэкенд случайно выбирает 3 карты и их положения, ИИ трактует расклад.

## Принятые решения
| Тема | Решение |
|---|---|
| Язык | Python |
| Фреймворк | aiogram 3 (рекомендация) |
| База данных | PostgreSQL + SQLAlchemy + Alembic (рекомендация) |
| ИИ-модель | бесплатная на старте; провайдер должен легко заменяться |
| Проект | новый |
| Колода | все 78 карт; позже несколько колод на выбор пользователя |
| Изображения | пользователь подбирает сам |
| Перевёрнутые карты | изображение показывается перевёрнутым; в том числе для карты дня |
| Карта дня | у каждого пользователя своя случайная |
| Повторный запрос карты дня | ответ «вы уже получили карту дня» |
| Начало суток | полночь по часовому поясу пользователя |
| Рассылка | в фиксированное время; если пользователь уже взял карту сам, рассылка ничего не присылает |
| Позиции в раскладе | без позиций, карты читаются вместе |
| Ограничения на расклады | в первой итерации нет (платные расклады позже) |
| Отправка расклада | альбом из 3 фото, затем текст отдельным сообщением (подпись к альбому видна только у одного фото и ограничена 1024 символами) |
| Ограничения тем вопросов | прописываются в промпте |
| Уточняющие вопросы после расклада | нет |
| Язык бота | только русский |
| Админка, аналитика | не в первой итерации |

## Этапы

### Этап 0. Каркас проекта
- Python, менеджер зависимостей (uv или poetry), aiogram 3, SQLAlchemy, Alembic.
- Настройки (токен бота, ключ ИИ, адрес базы) берутся из `.env`.
- `docker-compose` с Postgres для локальной разработки.
- Бот получает сообщения через polling; способ работы на сервере решим позже.

### Этап 1. Структура данных
Значение карты одно и то же, картинки зависят от колоды, поэтому новые колоды добавляются без переделки.

| Таблица | Поля |
|---|---|
| `cards` | 78 карт: код, название на русском, аркан, масть, номер |
| `decks` | колоды; пока одна |
| `deck_card_images` | колода, карта, путь к картинке, `file_id` Telegram для прямого и перевёрнутого положения |
| `users` | Telegram ID, имя, username, часовой пояс, подписка, выбранная колода (на будущее), поля профиля (позже) |
| `daily_cards` | пользователь, дата по его часовому поясу, карта, положение, описание, источник (сам взял / рассылка); **уникальная пара «пользователь + дата»** |
| `spreads` | вопрос, 3 карты с положениями, ответ ИИ; только если решим хранить историю |

Уникальная пара «пользователь + дата» гарантирует, что при двойном нажатии или одновременной рассылке пользователь не получит две карты.

### Этап 2. Колода и изображения
- Скрипт заполняет базу 78 картами.
- Перевёрнутые картинки один раз генерируются поворотом на 180° через Pillow.
- После первой отправки в Telegram сохраняется `file_id`; дальше картинка шлётся по нему без повторной загрузки.

### Этап 3. Основа бота
- `/start`: регистрация пользователя и запрос часового пояса (способ не выбран).
- Главное меню: «Карта дня», «Расклад», «Подписка».

### Этап 4. Работа с ИИ
- Общий интерфейс `generate(prompt)`; первым подключается один бесплатный провайдер.
- Шаблоны запросов для карты дня и расклада (текст пишем позже).
- Таймауты, повтор при ошибке, обработка превышения лимитов.
- Учесть: на бесплатных уровнях провайдер может использовать запросы для обучения моделей, а вопросы пользователей бывают личными.

### Этап 5. Карта дня
1. Вычислить сегодняшнюю дату по часовому поясу пользователя.
2. Если запись на эту дату есть — ответить «вы уже получили карту дня».
3. Если нет:
   - случайно выбрать карту и положение (`secrets` / `SystemRandom`);
   - сохранить запись;
   - получить описание от ИИ;
   - отправить фото с описанием.

### Этап 6. Подписка и рассылка
- Кнопка подписки / отписки.
- Фоновая задача каждые N минут находит подписчиков, у которых наступило время рассылки и нет карты на сегодня, и выдаёт им карту по логике этапа 5.
- Отправка очередью с ограничением скорости (лимиты Telegram и бесплатной ИИ-модели).

### Этап 7. Расклад из трёх карт
1. Пользователь нажимает «Расклад», бот просит вопрос и ждёт ответа.
2. Бот выбирает 3 разные случайные карты, положение каждой случайное.
3. В запрос к ИИ идут вопрос, карты с положениями и данные профиля.
4. Пока ИИ отвечает, бот показывает «печатает…».
5. Отправка альбома из 3 фото, затем текста трактовки.

### Этап 8. Проверка и запуск
- Тесты:
  - выдача карты дня на границе суток в разных часовых поясах;
  - нет повторной карты за день;
  - рассылка пропускает тех, кто уже взял карту сам.
- Развёртывание на сервер (место не выбрано).

## Открытые вопросы
1. **Как узнать часовой пояс.** Блокирует доработку карты дня.
2. **Время рассылки**: одно местное время у всех (например, 9:00 по часовому поясу каждого) или один момент для всех?
3. **Описание карты дня**: генерировать персонально или брать из заранее подготовленного набора (зависит от лимитов модели).
4. **Ошибка ИИ**: сохранить карту и показать с описанием при следующем нажатии, или не выдавать карту, пока ИИ не ответит?
5. **Хранить ли историю раскладов** в базе (бот не может читать переписку).
6. **Отписка и смена часового пояса**: устраивают ли кнопка «Подписка» в меню и отдельная команда для смены часового пояса?
7. **Поля профиля**: какие собирать и когда.
8. **Хостинг**: где будет работать бот, webhook или polling.
9. **Конкретная бесплатная модель**: выбрать после проверки актуальных лимитов.
10. **Промпты**: тон, длина, дисклеймер.

Этапы 0–3 от открытых вопросов почти не зависят (кроме способа запроса часового пояса) и могут начинаться сразу.
